# Combined CORE Staging Firmware Plan (v27)

**Goal:** Combine simultaneous wireless Mouse (`HID_0`), Vendor Configuration Feature (`HID_1`), and Auxiliary HID (`HID_2`: Consumer/System/Keyboard/Vendor notifications) on local prototype USB IDs (`2FE3:0008`), adding the complete CORE startup command allowlist, battery query, receiver-local firmware version (`00/00/81`), and offline `0xA4` status before any stock USB ID (`258A:2031`) or CORE launch.

## Architecture (`-App core-proto`, `CORE_PROTO_FULL`)

1. **Three USB HID instances + CDC (`CONFIG_USB_HID_DEVICE_COUNT=3`)**:
   - `HID_0`: Mouse (`0001:0002`, 6-byte report, live automatic wireless pointer control enabled).
   - `HID_1`: Vendor Config Feature (`FFFF:0000`, 64-byte Feature report).
   - `HID_2`: Auxiliary HID (`000C:0001` ID 1, `0001:0080` ID 2, `0001:0006` ID 3 + LED Output, `FFA0:0001` ID 4, `FFFF:0001` ID 5).
   - Prototype identity `2FE3:0008`, product `DIY Mouse CORE Proto v27` — CORE cannot attach prematurely.
2. **Receiver-local version & offline status (`config_hid.h`)**:
   - Target `00 / 00 / 81` (size 3) answers locally with `A1 00 00 03 00 81 01 00 00 00` without touching RF.
   - Mouse-targeted requests (`target == 0x02`) when the mouse is unlinked (`!probe_sent`) immediately publish `0xA4` ("Wireless-Receiver Did Not Find Device") instead of waiting 4 seconds or locking out the receiver.
   - Once a completed transaction is published (`config_hid_published`), a subsequent `SET_REPORT` is accepted even if the host omitted an intermediate `GET_REPORT` (matching CORE's fire-and-forget `SetFeatureReport` calls).
3. **CORE startup command allowlist (`config_read.h`)**:
   - **Getters**: `00/81` (version), `00/83` (battery), `00/85` (active profile), `00/88` (debounce), `01/80` (polling), `01/81` (DPI stages), `01/82` (selected DPI stage), `01/88` (LOD), `02/81` (DPI colours), `03/80` (slot-0 bindings).
   - **Setters**: `00/05` (active profile 1..3), `00/08` (debounce profile 1..3, 0..16 ms), `01/00` (polling divider `{1,2,4,8}`), `01/01` (DPI stages profile 1..3, count 1..6, 50..19000 step 50), `01/02` (selected DPI stage profile 1..3, stage 1..6), `01/08` (LOD `{1,2}`), `02/01` (DPI colours profile 1..3, 18 RGB bytes), `03/00` (slot-0 bindings profile 1..3, 8 known button IDs, slot 0).
   - **Rejected**: firmware updater, bootloader, RF address, pairing, factory reset, macro bodies, unknown groups/ops, and out-of-range fields.
4. **Shared RF frame walking**:
   - `aux_hid_frame_valid` and `config_read_frame_valid` accept mixed RF packets containing types `1..7` when `CORE_PROTO_FULL` is enabled (continuation bit permitted on type `7` only).
   - `wireless_hid_forward` skips type `7` records and forwards types `1..6` with per-sequence bitmask deduplication.
   - `config_read_receive` walks variable-length records (`1..7`) and processes only type `7` replies.
5. **Verification**: Native C unit tests (`firmware/test_core_proto.c`, `firmware/test_core_proto.py`) verify all 15 tests pass, followed by `-App core-proto` build and UF2 validation. Existing `dongle`, `config-hid`, and `aux-hid` targets remain unchanged.
